
- refactor(acts): the scheduler shell's split modules are wired in, and the store-facing timers are the kernel host's own serve ticks. `shell/mod.rs` shrinks from 3993 to ~2300 lines: `admission`, `delivery`, `lifecycle`, `liveness`, `recovery`, `snapshot` and `timers` are declared submodules now (their previously inline twins are deleted; the extracts were verbatim lifts, so this is a move), the shared health module moves to `scheduler::core::health` (the deterministic core now owns `LoopGuard`/`SchedulerHealth`/`KernelSchedule`/`TimerGuards`/the metrics gauges; `shell::health` and the duplicated metric structs in both `shell/mod.rs` and `runtime.rs` are gone), and `SnapshotRegistry` lives with the shell instead of the runtime. The four store-facing timers (schedule triggers, message retries, terminal cleanup, snapshot TTL purge) no longer spawn their own tasks: `TimerGuider` exposes one `*_tick` pass each, `KernelSchedule` carries their four intervals, and `KernelHost::serve` ticks them from the same `select!` that drives ready/recovery/outbox/projection — one background task, one store-touching service, so a timer pass can never run concurrently with another background pass or delay an operation out of band. `Runtime`'s `init_retry_timer`/`init_cleanup_timer`/`init_trigger_timer`/`init_snapshot_timer` (and the interval/schedule helpers behind them) are deleted: `Runtime::create` attaches the guider to the host, `Runtime::timers()`/`router()`/`writer()` are the timers' accessors, `TimerGuards` is the single timer-health state `scheduler_health` reads, and `Engine::start`'s boot section no longer starts anything. The cleanup loop keeps its test contract (a no-op under `cfg(test)`; the reliability cells drive `Runtime::sweep_removable` explicitly), and the timer suite drives each pass directly, pinning that one tick is one pass.
